# Sebason

Версия 2.39.1. Номер живёт в `src/lib/version.ts` и в `package.json`, виден
внизу настроек. Поднимается с каждым изменением.

Дневник роста малыша: сон, вес и рост, вехи развития, статистика.

Интерфейс английский, русский включается флагом в настройках и на экране
входа. Подробности — в разделе «Два языка».

Приложение работает **офлайн**. Все записи сначала попадают в локальную базу
браузера (IndexedDB) и только потом уезжают в Supabase. Ночью в детской с
плохим Wi-Fi таймер сна запускается мгновенно — сеть на это никак не влияет.

---

## Два языка

Основной язык английский, русский — выбором. Флаги стоят в трёх местах, где
они нужны: справа в шапке настроек, в углу экрана входа и в углу первого
экрана «Добавить малыша». До входа настройки недоступны, поэтому переключатель
там же — иначе русскоязычный родитель упирается в английский экран.

Флаги нарисованы своими SVG, а не эмодзи: эмодзи-флаги не отображаются в
Windows и по-разному выглядят на телефоне и в браузере. Каждый язык подписан
на себе самом — «English» и «Русский», как принято у переключателей.

Выбор хранится в локальных настройках устройства, не в базе: у мамы может быть
русский, у папы английский, записи от этого не меняются. На уже установленном
приложении язык станет английским — в сохранённых настройках поля `language`
нет, а по умолчанию теперь `en`.

### Как устроено внутри

Своего словаря хватило, библиотеку не брали. Ключ перевода — это сама русская
строка:

```tsx
<Button>{t("Добавить сон")}</Button>
{t("до сна {0}", [formatDuration(untilBedtime)])}
{withCount(days, "день")}
```

Так переезд обошёлся без выдумывания восьмисот идентификаторов, а главное —
**если английского перевода нет, показывается сам ключ, то есть русский
текст**. Экран не пустеет и не ломается никогда; худшее, что бывает, —
непереведённая надпись, которую видно глазом.

- `lib/i18n.ts` — `t()`, `locale()`, формы слов при числе;
- `lib/i18n.en.ts` — словарь, 584 пары, по алфавиту: дырки видно глазами;
- `lib/i18n.plural.ts` — формы: в русском их три, в английском две, поэтому на
  месте вызова остаётся только слово — `withCount(3, "день")`.

Одна ловушка стоила отдельной правки: словари и списки, собранные на уровне
модуля, считают перевод один раз при загрузке — и застывают на языке, который
был в тот момент. Так подписи вкладок внизу оставались на старом языке до
перезагрузки. Вкладки теперь хранят ключ и переводятся при отрисовке, а
названия лекарств, величин ВОЗ и подписи периодов сделаны геттерами: значение
считается при каждом обращении.

Даты и числа идут через `locale()`: `ru-RU` или `en-GB`. Британская, потому
что часы в приложении 24-часовые. Оттуда же берётся десятичный разделитель —
«38,6 °C» по-русски и «38.6 °C» по-английски. Поля ввода тоже: подсказка в
поле веса — «7,25» или «7.25», и сохранённое значение подставляется обратно с
привычным разделителем. Разбор принимает и запятую, и точку.

Уведомления с сервера переводятся отдельно: у подписки в
`push_subscriptions` появилась колонка `locale`, и Edge Function собирает текст
под язык того телефона, куда его отправляет. У родителей язык может быть
разный, а напоминание уходит на оба.

**Нужно обновить схему:** в `push_subscriptions` добавилась колонка `locale`.

### Как проверялось

В браузере, с обходом всех экранов на английском: экран входа, онбординг, все
пять вкладок с развёрнутыми карточками, шторки сна, кормления, температуры,
лекарства, измерения и выгрузка для врача. На каждом шаге текст страницы
проверялся регуляркой на кириллицу — не нашлось нигде. Отдельно проверено
переключение на русский и обратно.

## Синхронизация между телефонами (Supabase)

Бесплатного тарифа хватает с большим запасом.

### 1. Создать проект

Зайти на [supabase.com](https://supabase.com), создать новый проект.
Регион лучше выбрать поближе.

### 2. Применить схему

Supabase → **SQL Editor** → **New query** → вставить целиком содержимое
[`supabase/schema.sql`](supabase/schema.sql) → **Run**.

Скрипт создаёт таблицы, индексы и политики доступа. Его безопасно
запускать повторно — например, после обновления схемы.

### 3. Прописать ключи

```bash
cp .env.example .env.local
```

Значения взять в Supabase → **Project Settings** → **API**:

| Переменная | Что подставить |
| --- | --- |
| `VITE_SUPABASE_URL` | Project URL |
| `VITE_SUPABASE_ANON_KEY` | `anon` `public` key |

`anon key` — публичный ключ, его не страшно держать в приложении: доступ к
данным ограничен политиками RLS из схемы. Файл `.env.local` в git не
попадает.

Перезапустить `npm run dev`.

### 4. Включить вход через Google

Приложение открывается экраном входа: профиль малыша заводится уже внутри
аккаунта, чтобы записи сразу принадлежали семье.

**Google Cloud Console** → [console.cloud.google.com](https://console.cloud.google.com):

1. Создать проект (или взять существующий)
2. **APIs & Services** → **OAuth consent screen** → тип **External**,
   заполнить название и почту поддержки. Пока приложение в режиме Testing,
   добавьте себя и жену в **Test users** — иначе Google не пустит
3. **APIs & Services** → **Credentials** → **Create credentials** →
   **OAuth client ID** → тип **Web application**
4. В **Authorized redirect URIs** вставить адрес, который Supabase показывает
   в Authentication → Providers → Google. Он выглядит так:

   ```
   https://<ваш-проект>.supabase.co/auth/v1/callback
   ```

**Supabase** → **Authentication** → **Providers** → **Google**:

5. Включить провайдер, вставить **Client ID** и **Client Secret** из шага 3

> Client Secret вставляется именно здесь, а не в `.env`. Всё, что в этом
> проекте начинается с `VITE_`, попадает в собранный файл и уезжает в браузер
> к каждому, кто открыл страницу — секрет утёк бы сразу.

**Supabase** → **Authentication** → **URL Configuration**:

6. В **Redirect URLs** добавить адреса, откуда открываете приложение:

   ```
   http://localhost:5173/**
   https://ваш-боевой-адрес/**
   ```

   Без этого Supabase откажется возвращать пользователя обратно.

### 5. Настроить письмо с кодом

Вход сделан по одноразовому коду из письма — так удобнее в приложении на
телефоне, чем по ссылке, которая выкидывает в браузер.

Supabase → **Authentication** → **Emails** → шаблон **Magic Link** →
добавить в текст письма строку:

```
Код для входа: {{ .Token }}
```

Без этой правки в письме будет только ссылка, и поле «Код из письма» в
настройках окажется бесполезным.

Вход по коду из письма оставлен как запасной вариант — на случай, если
Google почему-то недоступен.

### 6. Войти

Открыть приложение и нажать **Войти через Google**. При первом входе
автоматически создаётся «семья».

### Общий доступ для второго родителя

В настройках → Синхронизация есть кнопка **«Поделиться»**: она отправляет
ссылку вида `.../#/join/A1B2C3`. Второй родитель открывает её, входит в свой
аккаунт — и попадает в семью автоматически.

Можно и вручную: код из шести символов вводится в поле «Код приглашения» —
оно есть и в настройках, и на экране приветствия, если малыш ещё не заведён.

При присоединении пустая семья, которая создалась при первом входе,
удаляется — иначе `my_family_id()` продолжал бы возвращать её, и второй
родитель не увидел бы общих записей.

### Защита хранилища

При первом запуске приложение просит у браузера постоянное хранилище
(`navigator.storage.persist()`). Без этого браузер вправе удалить дневник при
нехватке места. Состояние и занятый объём видны в настройках, там же кнопка
запросить защиту повторно.

## Резервная копия

Настройки → **Резервная копия** → «Выгрузить файл». Получится JSON со всеми
записями. Загрузка обратно не затирает более свежие данные — сравниваются
времена изменения, так что файл можно применять поверх текущих.

Стоит делать раз в пару месяцев: браузер может очистить своё хранилище.

### Как устроена синхронизация

У каждой записи есть `updated_at` (ставит устройство) и `synced_at` (ставит
сервер).

- **Когда.** Через пару секунд после любой записи, при возврате в приложение,
  при появлении сети, по жесту «потянуть вниз» и раз в минуту фоном.
- **Отправка.** Всё, что помечено локальным флагом `_dirty`, уходит на сервер
  через `upsert`. Если сервер ответил ошибкой, флаг не снимается — запись
  уедет при следующей попытке.
- **Загрузка.** Забираем всё, у чего `synced_at` больше сохранённого курсора.
- **Конфликты.** Побеждает запись с более поздним `updated_at`.
- **Удаление.** Мягкое — запись помечается `deleted`, иначе удаление никогда
  не доехало бы до второго телефона.

Разделение `updated_at` и `synced_at` не случайно: часы на телефоне могут
отставать, и если бы курсор считался по клиентскому времени, часть записей
проскакивала бы мимо.

## Переключение периода свайпом

Переключатель 7 / 14 / 30 в статистике листается пальцем: влево — следующий
период, вправо — предыдущий. По кругу не ходит: на «7 дней» свайп вправо и на
«30 дней» свайп влево ничего не делают.

Жест срабатывает от 45 пикселей и только если движение горизонтальное —
вертикальное отдаётся прокрутке страницы.

По умолчанию выбрана неделя, и она показывается всегда: даже один день записей —
это уже график, а пустые места карточки объясняют сами. Раньше карточки сна
прятались целиком, пока не наберётся два дня, — и график было просто не найти.

Если полных суток ещё нет (у самого раннего дня отрезано утро, у сегодняшнего
вечер), вместо среднего стоит прочерк и объяснение, а не «нет данных» над
видимыми столбиками.

Все три периода доступны всегда — состав кнопок не меняется под руками. Но
если для «14» или «30 дней» истории не хватает, вместо карточек показывается
одна строка: «Данных за 30 дней пока нет. Записи есть только за 9 дней — выберите
период покороче». Цифры не рисуются вовсе: «Итоги за месяц», посчитанные по
девяти дням, вводили бы в заблуждение.

История считается в календарных днях — так же, как её группируют графики.

## Как считается сон за сутки

График «Сон по дням», кольцо и статистика режут сон по календарным суткам:
ночь с 23:00 до 08:00 даёт час одному дню и восемь следующему. Лента истории
относит сон к тем суткам, когда он начался, — вся ночь идёт в вечер. На
непрерывных данных обе методики дают одно и то же число: каждый день теряет
хвост своей ночи и получает хвост предыдущей.

Из средних исключаются двое суток: сегодняшние — они не закончились, и самые
первые в истории — у них нет предыдущей ночи, поэтому сумма всегда занижена.
Оба показаны бледным столбиком.

## История

Одна лента вместо двух: сон и кормления идут вперемешку по времени,
сгруппированные по дням. В шапке дня — сумма сна и число кормлений. Иконка
задаёт вид записи: фиолетовая луна — ночной сон, зелёное солнце — дневной,
оранжевая бутылочка — кормление. Нажатие открывает правку той записи, которой
строка принадлежит; в шапке две кнопки добавления — «Сон» и «Кормление».

Карточки «Сон» и «Кормления» вверху страницы списков не показывают — они
повторяли бы эту ленту в другом виде. Там только «что сейчас»: идущий сон или
кормление с таймером, когда было последнее и итог за сегодня.

Стоят рядом, если хватает ширины, и переносятся друг под друга, если нет:
минимум на карточку 260 пикселей. Карточка сна построена на стилях карточки
кормлений — отличается только тон, чтобы они не разъезжались со временем.

### Кормление перед сном

Если у ночного сна нет кормления в предшествующие полтора часа, под строкой
появляется подсказка и две кнопки. «Добавить» открывает форму кормления с уже готовым
отрезком: пятнадцать минут перед засыпанием. Для сна с 12:00 это 11:45 — 12:00,
остаётся выбрать, чем кормили. «Не было» помечает этот сон
полем `no_feed_before`, и подсказка исчезает — отметка живёт в записи, а не в
браузере, иначе второй родитель продолжал бы видеть напоминание.

Подсказка только у ночных снов: у дневных она висела бы на каждой второй
строке.

## Поля даты и времени

Окончание у новой записи всегда пустое — с подписью «пусто — сон ещё идёт».
Заполняет его родитель, приложение ничего не угадывает. Исключение одно:
подсказка про кормление перед сном, где отрезок предлагается целиком.

Выбрали дату — фокус сам переходит на время и открывается его выбор: одна
дата без времени записи не даёт, а возвращаться к полю руками неудобно.

Поле держит незаконченный ввод у себя. Раньше введённое время без даты
молча выбрасывалось — казалось, что нажатие не сработало, — а введённая
дата подставляла время 12:00, которое никто не выбирал. Теперь время
достраивается датой начала записи, а дата ждёт времени, ничего не выдумывая.

## Удаление и отмена

Записи сна, кормления и измерений удаляются сразу, без вопроса — вместо него
внизу появляется плашка «Удалено · Отменить» с полоской обратного отсчёта.
Две секунды на передумать.

Профиль малыша удаляется с подтверждением: вместе с ним уходят все его
записи. Отмена есть и здесь и возвращает всё разом — кроме того, что было
удалено раньше по отдельности.

Технически удаление всегда мягкое: запись помечается `deleted`, а не
стирается. Отмена снимает пометку и отправляет изменение на сервер как
обычную правку.

## Ночной режим

Отдельный переключатель в настройках, в карточке «Вид». Перекрывает выбранную
тему — работает и поверх светлой.

**Включается по расписанию**, а не вручную: ночью настройки не открывают.
Переключатель означает «пользоваться расписанием», под ним два поля — с какого
часа и до какого. По умолчанию 00:00–07:00, окно через полночь (22:00–07:00)
тоже работает. Приложение пересчитывает состояние раз в полминуты и при
возврате на экран, так что режим включается и выключается сам.

Если сейчас день, под полем написано «сейчас день — включится в 00:00» —
иначе непонятно, почему переключатель включён, а ничего не изменилось.

Что меняется: почти чёрный тёплый фон, вся палитра уходит в янтарь, синего в
интерфейсе не остаётся (он сильнее прочих подавляет мелатонин), кнопки
«Проснулся» и «Кормлю» вырастают с 56 до 68 px, крупная цифра таймера
увеличивается, фотографии приглушаются. Цвет строки состояния телефона
перекрашивается вместе с приложением.

## Левая и правая грудь

В настройках есть тумблер «Различать грудь», **выключенный по умолчанию**.

- **Выключен** — кормление записывается как просто «грудь». Одна кнопка, ничего
  выбирать не надо.
- **Включён** — записываются левая и правая отдельно, и приложение предлагает
  ту сторону, которой не кормили в прошлый раз.

Тумблер меняет только то, как записываются **новые** кормления. Уже сделанные
записи он не переписывает: если однажды отмечена левая, она останется левой.
Поэтому в редакторе поле «Сторона» показывается не только при включённой
настройке, но и у любой записи, где сторона уже стоит, — иначе сохранение
молча стёрло бы её. В этом поле есть третий вариант «Не важно», чтобы сторону
можно было снять осознанно.

**Нужно обновить схему в Supabase.** Значение `breast` без стороны новое, и
старое ограничение `feedings_kind_check` его отвергнет. Запустите
`supabase/schema.sql` заново — проверка пересоздаётся, повторный запуск
безопасен.

## Ночные кормления

Мама часто засыпает вместе с ребёнком, и ночь записывается одним куском на
девять-десять часов — хотя на самом деле малыш просыпался поесть.

Поэтому после нажатия «Проснулся», если сон был **ночным и длился больше
двух часов**, приложение спрашивает: были ли кормления, сколько раз, чем и по
сколько миллилитров.

Время не спрашивается и не выдумывается: количество, чем кормили и объём
хранятся прямо в записи ночного сна (`night_feedings`, `night_feeding_kind`,
`night_feeding_ml`). Отдельных кормлений с придуманным временем не
создаётся — иначе лента суток и список кормлений заполнялись бы вымыслом.

Отметка видна в истории сна («3 кормления · грудь»), правится через обычный
редактор записи и попадает в статистику отдельной строкой «Кормлений за
ночь». «Не было» записывает ноль, а не пустоту — чтобы отличать «кормлений не
было» от «не отмечали».

## Уведомления

Работают только в приложении, установленном на домашний экран (iOS 16.4+,
Android). Включаются в настройках, разрешение спрашивается по нажатию.

Что приходит: за 30 минут до отхода ко сну, в само время сна, и когда
бодрствование затянулось дольше возрастного ориентира. Пока малыш спит,
уведомления не приходят. Каждое срабатывает один раз.

Работают в двух режимах. **Локальный** — страница ставит уведомление сама,
пока приложение открыто или недавно свёрнуто. **Серверный (Web Push)** —
приходит даже при закрытом приложении; для него нужна разовая настройка,
описанная ниже.

Если серверный не настроен, приложение честно пишет об этом в настройках при
включении переключателя.

## Серверные уведомления: настройка

Разовая процедура. Без неё приложение работает, просто напоминания приходят
только пока оно в памяти.

### 1. Сгенерировать пару ключей

```bash
npx web-push generate-vapid-keys
```

Публичный ключ → в `.env` как `VITE_VAPID_PUBLIC_KEY`.
Приватный никуда в проект не кладём — он пойдёт в секреты функции.

### 2. Применить схему

Supabase → SQL Editor → выполнить `supabase/schema.sql` целиком. Добавятся
`push_subscriptions`, `push_log` и поля времени сна у ребёнка.

### 3. Развернуть функцию

Панель Supabase функции не разворачивает — нужен CLI. Он уже стоит в
проекте как зависимость, ставить отдельно (через Homebrew) не надо:

```bash
npx supabase login
npx supabase link --project-ref <PROJECT_REF>
npm run functions:deploy
```

Секреты задаются либо в панели — **Edge Functions → Secrets**, — либо той же
командой:

```bash
npx supabase secrets set \
  VAPID_PUBLIC_KEY=<публичный> \
  VAPID_PRIVATE_KEY=<приватный> \
  VAPID_SUBJECT=mailto:вы@example.com \
  CRON_SECRET=<любая длинная строка>
```

Про флаги в `functions:deploy`: `--no-verify-jwt` обязателен, потому что
функцию вызывает планировщик базы, а не пользователь (от чужих вызовов её
защищает `CRON_SECRET`); `--use-api` собирает функцию на стороне Supabase,
чтобы не требовался локальный Docker.

`SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` задавать не нужно — Supabase
подставляет их в функцию сам.

### 4. Включить расписание

Скопировать `supabase/cron.sql.example` в `supabase/cron.sql`, заменить в
копии `PROJECT_REF` и `CRON_SECRET` на свои значения и выполнить в SQL Editor.

Копия с настоящим секретом в git не попадает — она в `.gitignore`. В
репозитории остаётся только шаблон. Функция начнёт вызываться раз в
десять минут.

Проверить, что задание живо:

```sql
select status, return_message, start_time
  from cron.job_run_details
 where jobid = (select jobid from cron.job where jobname = 'sebason-push')
 order by start_time desc limit 10;
```

### 5. Подписаться

Перезапустить сборку (ключ читается при старте), в приложении включить
переключатель уведомлений. Появится строка «Уведомления придут, даже если
приложение закрыто» — значит подписка сохранена.

### Как это устроено

- Своё устройство подписывается через `pushManager.subscribe` и кладёт
  endpoint и ключи в `push_subscriptions`. По строке на устройство.
- Функция раз в десять минут проходит по семьям, у которых есть подписки,
  считает по каждому ребёнку — не пора ли укладываться, не затянулось ли
  бодрствование, — и рассылает push всем устройствам семьи.
- Повторы отсекает `push_log` с составным первичным ключом: вторая попытка
  отправить то же самое просто не вставится.
- Время считается в часовом поясе устройства — он сохраняется вместе с
  подпиской. Пока малыш спит, уведомления не шлются.
- Если Apple или Google отвечают, что подписка мертва (404 или 410), строка
  удаляется сама.

**iOS:** работает только в приложении, установленном на домашний экран,
iOS 16.4 и новее. В обычном Safari push не приходит вовсе.

## Контроль болезни

Вкладка «Болезнь» вместо прежних «Вех». Пока болезни нет, на экране одна
кнопка — «Заболел»: выбирать не из чего, она заводит первый замер, с него
болезнь и начинается. Дальше появляются «Температура» и «Лекарство» и общий
журнал: замеры и выданные лекарства идут одной лентой по времени, чтобы было видно, что дали и как температура повела себя дальше. В
шапке каждого дня рядом с «Сегодня» стоит число — журнал показывают врачу, и
относительной подписи ему мало.

**Температура:** дата-время, значение и способ — лоб (по умолчанию),
подмышка, ректально. Порог жара у каждого способа свой, потому что одна и та
же температура тела даёт разные показания: подмышкой 37,5, лоб 37,8,
ректально 38,0 °C. Приложение подписывает уровень — «в норме», «повышенная», «высокая» — и
красит цифру: зелёным в норме, жёлтым чуть выше, красным когда плохо.

Вторая граница, красная, зависит от возраста: у младенца до трёх месяцев
тревожен любой жар, а двухлетний спокойно переносит то, из-за чего к
трёхмесячному вызывают врача. Запас над порогом растёт с возрастом — 0 до
трёх месяцев, 0,8 до полугода, 1,2 до двух лет, дальше 1,6 °C. Под цифрой
всегда написаны конкретные границы для этого ребёнка и способа, и оговорка,
что это ориентиры, а не диагноз.

**Лекарство:** дата-время, что дали и количество. Вместо ввода названия —
три кнопки: «Нурофен», «Свечи» и «Другое». По умолчанию выбраны свечи.
Нурофен сразу ставит миллилитры, свечи — миллиграммы; переключатель единиц остаётся рабочим, это подсказка, а
не запрет. «Другое» открывает поле для своего названия.

**График.** Кривая температуры за текущую болезнь: точки покрашены каждая по
своему уровню, пунктиром — порог жара и тревожная граница для возраста,
треугольниками снизу — когда давали лекарство, так что видно, спала ли
температура после дозы. По оси — часы, шаг подбирается под длину отрезка: на
сутках через три часа, на двух днях через шесть, дальше реже. Полночь помечена
пунктиром пожирнее и датой.

**Выгрузка для врача.** Свёрнутая карточка внизу: один лист с именем,
возрастом, числом замеров, пиком, графиком и всем журналом по дням.
«Картинкой» сохраняет PNG (на телефоне предлагает отправить сразу), «В PDF»
открывает печать — на листе остаётся только сам отчёт, без меню и кнопок.

Лист нарисован одним SVG с цветами прямо в атрибутах: сериализованная
картинка теряет внешние стили, и без этого PNG вышел бы чёрным по чёрному.
Математика графика вынесена в `feverModel` — экран и выгрузка считают кривую
одним и тем же кодом, иначе они рано или поздно разошлись бы.

Карточка графика стоит под журналом и свёрнута — при болезни чаще нужен свежий замер,
а не кривая.

Линия рвётся там, где между замерами прошло больше восьми часов: ночью никто
не мерил, и рисовать через этот провал уверенную прямую было бы выдумкой.
Границы пунктира — для того способа, которым мерили чаще всего за отрезок; он
назван под графиком, потому что для разных способов пороги разные.

**Когда можно снова.** Отсчёт живёт прямо в строке журнала, рядом с меткой
«лекарство»: у самой свежей выдачи — жёлтое «3 ч 59 мин», а когда шесть часов
прошли — зелёное «можно давать». Дали то же лекарство ещё раз — таймер сам
оказывается на новой записи, старая остаётся с одной меткой.

В строке журнала название короткое — «Свечи», а не «Свечи (парацетамол)»:
полное занимало три строки и наезжало на таймер. В выгрузке для врача имя
остаётся полным.

Отсчёт у каждого препарата свой: нурофен и парацетамол друг другу не мешают.

Для своего лекарства из «Другого» отсчёта нет: приложение не знает, что это
за препарат, и придумывать интервал не должно.

При включённых уведомлениях, когда интервал прошёл, приходит напоминание
«Можно дать лекарство». Каждое напоминание отправляется один раз — ключ
привязан ко времени готовности, а не к моменту проверки.

Карточка «Сейчас» показывает последний замер, пик и сколько времени идёт
наблюдение. Череда замеров считается одной болезнью, пока перерыв между ними
меньше полутора суток: иначе давняя простуда склеилась бы с новой.

**«Поправился».** Ждать полутора суток не всегда нужно — кнопка в правом
верхнем углу карточки закрывает болезнь сразу. Нажатие не срабатывает молча:
карточка на время подменяется вопросом «Завершить болезнь?» с «Отменить» и
«Подтвердить». Отмена возвращает прежний вид, болезнь идёт дальше.

После подтверждения экран возвращается к началу: сверху снова «Заболел» — с
этого и начинают новую болезнь. Вся прошедшая уезжает в одну свёрнутую
карточку «Итог болезни»: длительность, даты начала и конца, пик, число
замеров и лекарств, а под ними — журнал только этого периода, график и
выгрузка для врача по нему же. Отдельных карточек на экране не остаётся:
болезнь кончилась, и листать её каждый день незачем.

Выгрузка внутри итога считается по одной болезни, а не по всем записям, —
врачу показывают конкретный эпизод.

В шапке итога сверху слева период: «Последняя болезнь: 1 сентября 2026 —
3 сентября 2026», под ним «Вернуть болезнь» слева и заголовок справа. Своей
строкой, потому что в одну с ними период не влезает: заголовок и кнопка
вдвоём занимают 281 пиксель из 324. Разворачивать карточку ради возврата не
нужно.

Даты в болезнях пишутся с годом целиком — записи живут годами, и «1 сентября»
без года через год ничего не скажет. Русская локаль дописывает «г.», в
подписи это лишнее, поэтому `formatFullDate` его срезает. Итог показывается полтора суток после отметки, дальше экран
возвращается к обычному виду с общим журналом.

**Одна карточка — одна болезнь.** Журнал, график и выгрузка под живой
карточкой показывают только идущую болезнь. Раньше журнал показывал всё
подряд, и новая болезнь выглядела продолжением прошлой: наверху честно стояло
«Замеров 1», а ниже лентой шли позавчерашние записи. Когда болезни нет, этих
карточек нет вовсе — все записи и так лежат в истории, каждая при своей
болезни.

**История болезней.** Когда начинается новая болезнь, прошлая не пропадает —
она уезжает в свёрнутую карточку «История болезней» внизу экрана. Строка на
болезнь: даты, длительность, пик, сколько было замеров и лекарств. Строка
разворачивается на месте в те же полные данные, что и в итоге: журнал этого
периода, график и выгрузка для врача.

Удаление живёт внизу карточки, под сноской: красная кнопка «Удалить болезнь»
во всю ширину с корзиной — та же «опасная зона», что и «Удалить профиль» внизу
формы малыша. Появляется, только когда болезнь раскрыта, и относится к ней.

Такая же кнопка стоит внизу «Итога болезни» — иначе свежую закрытую болезнь
удалить было бы нечем: в историю она уезжает только через полтора суток или
когда начнётся следующая. Там она видна и у свёрнутой карточки: `Card` рисует
`footer` независимо от того, развёрнута она или нет.
Возобновить болезнь из истории нельзя: там прошлое, и трогать его нечего — снять отметку
«поправился» можно только у свежего итога, пока он наверху.

«Удалить» сначала спрашивает: шторка «Удалить болезнь?» называет период и
считает, сколько записей пропадёт — «1 замер и 1 лекарство». Подтверждение
мягко убирает их разом: отдельной записи «болезнь» в базе нет, есть только
они. В тосте «Вернуть» возвращает всё целиком. Шторка своя, а не браузерный
`confirm`: тот выглядит чужим на телефоне и не закрывается свайпом, как всё
остальное здесь.

Журнал болезни, уехавшей в историю, только читается — строки не открывают
редактор. Прошлое правят редко, а промахнуться пальцем по чужой записи в
свёрнутой истории легко; выглядят такие строки соответственно, без вида
кнопки.

Длительность у закрытой болезни считается до отметки «поправился», у
незакрытой — от первого замера до последнего; это написано под списком, чтобы
цифры не выглядели точнее, чем есть. Болезнь из одного замера показывается без
длительности — считать там нечего.

Лекарства делятся по болезням по времени: до отметки «поправился», а если её
не было — пока приложение считает болезнь идущей, но не заходя в следующую.

Разбор записей на болезни живёт в `listSpells`: одна и та же функция даёт и
текущую болезнь, и историю, поэтому границы у них не разъезжаются. При равном
времени замер с отметкой «поправился» считается старшим — иначе первый замер
новой болезни, попавший в ту же минуту, прилипал бы к только что закрытой.

Отметка хранится полем `recovered_at` на последнем замере болезни, а не
отдельной таблицей: ради одного флага таблица избыточна, а так конец болезни
уезжает второму родителю обычной синхронизацией. Замер с отметкой обрывает
череду — новые замеры начинают следующую болезнь, а не продолжают прошлую.

**Нужно обновить схему:** добавились таблицы `temperatures` и `medicines`,
а в `temperatures` — колонка `recovered_at`. Запустите `supabase/schema.sql`
заново.

## Прогноз следующего сна

На карточке сна, пока малыш бодрствует: «следующий сон примерно в 15:16 —
через 59 мин».

Считается по медиане последних десяти промежутков бодрствования за две
недели. Медиана, а не среднее: один затянувшийся день не должен сдвигать
прогноз. Если своих записей меньше трёх, берётся середина возрастного
ориентира — под строкой всегда написано, на чём прогноз основан.

Показывается только при трёх условиях сразу:

1. **Уведомления включены** — и переключатель в настройках, и разрешение
   браузера. Прогноз — часть тех же напоминаний про сон и перегул, поэтому
   при выключенных уведомлениях его нет и на экране.
2. **Не идёт сон** — нечего прогнозировать, малыш уже спит.
3. **Не идёт кормление** — родитель занят, подсказка только мешает.

Когда условия не выполнены, на этом месте остаётся обычный возрастной
ориентир. Если расчётное время уже прошло, строка меняется на «пора
укладывать».

## Развитие ребёнка

Первая карточка в статистике, три строки: заголовок, вердикт и на чём он
основан. «Всё в ориентирах» / «Не всё в ориентирах» / «Данных пока мало» —
чтобы уставший родитель увидел главное, не читая графиков. По нажатию
раскрываются четыре показателя с числами.

Что проверяется:

- **вес, рост, окружность головы** — z-оценка по таблицам ВОЗ. В ориентире —
  от −2 до +2 стандартных отклонений, то есть коридор с 3-го по 97-й
  перцентиль;
- **сон** — средние сутки против возрастного ориентира; нужно хотя бы три
  полных дня записей, иначе показатель помечается как «нет данных».

Показатель без данных не портит вердикт, но и не идёт в зачёт: он показан
серым прочерком, и в подстрочнике видно, сколько показателей проверено.

Внизу раскрытой карточки стоит оговорка: это не медицинская оценка, а сверка
записей с таблицами ВОЗ, и вопросы здоровья решает педиатр.

## Из чего состоят сутки

Кольцо в статистике: ночной сон, дневной и бодрствование как доли суток, в
центре — сумма сна. Полосы и списки показывают величины, кольцо — пропорцию:
сколько от суток приходится на сон, видно без арифметики.

Нарисовано на голом SVG — один `<circle>` на сегмент, длина дуги задаётся
через `stroke-dasharray`, сдвиг — через `stroke-dashoffset`. Библиотека для
графиков не нужна; компонент `components/ui/Donut.tsx` принимает любой набор
сегментов и переиспользуем.

В подписях стоят часы, а не проценты. Три округлённых процента дают в сумме
то 99, то 101 — а пропорцию и так видно по кольцу.

Время записано как `13:36 ч`, а не `13 ч 36 мин`: длинная запись не влезала
в строку легенды на узком экране и обрезалась краем карточки. Подпись при
нехватке места усекается многоточием, а число остаётся целым — оно важнее.

## Режим суток

Диаграмма в статистике: строка на сутки, от полуночи до полуночи. Сон
отрезками — фиолетовый ночной, зелёный дневной. Под ними точками —
кормления. Когда режим устойчив, отрезки и точки выстраиваются в вертикальные
столбики; когда сбивается — рассыпаются.

Внутри карточки нет ни сетки по часам, ни отдельного блока с легендой:
подписи цветов уместились в одну строку под диаграммой. Скругление отрезков
маленькое — при полностью круглых концах короткий сон раздувался бы до
кружка и выглядел длиннее, чем был.

Отрезки непрерывные, а не по часовым клеткам: отбой в 21:30 стоит на 21:30,
а не размазан по клетке «21». Положение считается в долях суток, поэтому в
дни перевода стрелок 23- и 25-часовые сутки размечаются правильно.

Заодно исправлен цвет дневного сна. Раньше `--sleep` и `--nap` были двумя
оттенками фиолетового — на графике их было не различить. Теперь дневной сон
везде зелёный: `#36d25f` в тёмной теме и `#0f7a35` в светлой. Второй темнее
не для красоты — этим же цветом набран текст значка в истории сна, и на белом
фоне светло-зелёный давал контраст около 2:1, то есть был почти нечитаем.

## Что изменилось

Карточка в статистике: одиннадцать показателей сна и кормлений, посчитанных
за выбранный отрезок и за предыдущий такой же. Меняется вместе с
переключателем 7 / 14 / 30 дней.

Карточка не делает выводов и не даёт советов — только цифры и то, на чём они
посчитаны. Что это значит для конкретного ребёнка, решает родитель.

Три правила, чтобы цифра не соврала:

- **Оба отрезка считает один и тот же код.** Средние вынесены в
  `windowMetrics`, текущий и предыдущий отрезок проходят через неё
  одинаково. Разойдись расчёты хоть в мелочи — разница между ними перестала
  бы что-либо значить.
- **Округление до вычитания.** Сначала оба значения приводятся к той
  точности, с какой показаны, и только потом вычитаются. Иначе на границе
  округления «12 ч 30 мин» и «12 ч 31 мин» дали бы «+0 мин».
- **Виден объём выборки.** Под каждой строкой написано, по скольким дням,
  ночам, снам или промежуткам посчитано с каждой стороны — «по 6 дням против
  7». Показатель не появляется вовсе, если записей меньше трёх хотя бы с
  одной стороны, и тогда карточка пишет, сколько строк скрыто.

Сегодняшний день в средние не идёт — он ещё не закончился.

## Итоги периода

Первая карточка в статистике — сводка за выбранный период: сон, кормления,
рост и вес с перцентилями. Меняется вместе с переключателем 7 / 14 / 30 дней.

Нарисована как SVG, а не вёрсткой, — поэтому экспорт совпадает с тем, что на
экране, пиксель в пиксель.

- **«Картинкой»** — PNG шириной 1080. На телефоне открывает системное меню
  отправки, на компьютере скачивает файл.
- **«В PDF»** — открывает диалог печати. В нём выбрать «Сохранить как PDF».
  Печатная таблица стилей прячет всё, кроме карточки: ни меню, ни шапки, ни
  самих кнопок экспорта на листе не будет.

## Фото ребёнка

Только в форме малыша — при создании и при правке. Кнопка «Добавить»
открывает системный выбор файла; когда фото есть, рядом появляется «Убрать».
Отдельной кнопки для камеры нет: на телефоне тот же выбор файла и так
предлагает снять новое фото. Фото появляется в
кружке в шапке, в переключателе детей и в самой карточке; если фото нет,
остаётся первая буква имени.

После выбора файла открывается кадрирование: круглая рамка, снимок тянется
пальцем, ползунок приближает. Центр кадра выбирает родитель — у детских фото
он почти никогда не совпадает с центром снимка.

Файл читается целиком, а не через `createObjectURL`: временную ссылку
пришлось бы отзывать в очистке эффекта, а она в разработке срабатывает раньше,
чем картинка успевает загрузиться.

Выбранный квадрат сжимается до 256×256 JPEG — реальное
фото с телефона весит после этого около 20 КБ вместо пяти мегабайт. Хранится
как data URL прямо в записи ребёнка, поэтому уезжает в Supabase вместе со
строкой и виден второму родителю, а офлайн работает без отдельного хранилища.

**Нужно обновить схему:** в `children` добавилась колонка `photo`. Запустите
`supabase/schema.sql` заново.

## Семья в настройках

Наверху настроек — карточка «Семья»: кружок на каждого участника с
фотографией из аккаунта Google и именем под ним. Своё имя выделено жирным.
Рядом пунктирный кружок «Пригласить» — отправляет ссылку.

Имя и фотография берутся из метаданных Google (`full_name`, `avatar_url`) при
входе и хранятся в `family_members`. Если имени в аккаунте нет, берётся часть
почты до собачки. Если фотографии нет или она не загрузилась — в кружке
первая буква имени.

## Кто внёс запись

У каждой записи хранится автор (`created_by`), а у сна и кормления — ещё и
тот, кто нажал «Проснулся» или «Доел» (`ended_by`). Мама может уложить, а
папа поднять — видно обоих.

Имя и фотография участника берутся из аккаунта Google
(`family_members.display_name`, `avatar_url`).

Подпись показывается **только если в семье больше одного человека** — иначе
она ничего не сообщает. Своя запись подписана «вы», запись второго родителя —
его именем. Если начал и закончил один человек, показывается одно имя; если
разные — «уложили Мария · подняли вы».

Глаголы во множественном числе намеренно: род второго родителя приложению
неизвестен, и навязывать его нельзя.

**Где смотреть.** В списках подпись появляется только при двух и более
участниках. Внутри самой записи — при открытии сна или кормления — она
показывается всегда, даже если ты в семье один.

**Без входа автора нет вообще.** В режиме «только на этом устройстве»
записывать некого: пользователь один и аккаунта нет.

## Нормы ВОЗ

Коридоры на графике роста построены по **WHO Child Growth Standards** —
таблицам L, M, S из официального репозитория ВОЗ
([WorldHealthOrganization/anthro](https://github.com/WorldHealthOrganization/anthro),
файлы `weianthro.txt`, `lenanthro.txt`, `hcanthro.txt`).

В приложение таблицы вошли не целиком: вместо 1827 значений на каждый день
взята сетка из 118 точек — посуточно первые две недели, дальше понедельно до
года и помесячно до пяти лет. Между точками значения интерполируются.
Проверено: медиана расходится с полной таблицей не более чем на **0,054 %**,
сдвиг z-оценки не превышает **0,01**. Точка перехода на 24 месяцах, где ВОЗ
меняет измерение лёжа на измерение стоя, закреплена в сетке отдельно, чтобы
скачок не размазался.

Перцентиль считается по формуле LMS: `z = ((X/M)^L − 1) / (L·S)`. Для веса за
пределами ±3 SD применяется линейная поправка, предписанная ВОЗ.

Расчётные значения сверены с опубликованными таблицами ВОЗ: медиана веса
мальчика в 6 месяцев — 7,94 против 7,9; длина девочки в 12 месяцев — 74,0
против 74,0; 3-й перцентиль веса при рождении — 2,51 против 2,5.

## Оговорка

Возрастные ориентиры по сну — усреднённые справочные значения. Разброс между
здоровыми детьми огромный. Это подсказка «примерно пора», а не медицинская
рекомендация.

То же и с перцентилями роста: попадание в любую точку коридора ВОЗ — вариант
нормы. Значение имеет не отдельная цифра, а то, держится ли ребёнок своей
линии. Оценивает это педиатр.
